## 1. 時間與空間複雜度

**白話與用途：** 想找一本書，逐本翻和查目錄的成本不同。複雜度描述「資料變多時，工作量或額外記憶體怎麼成長」，幫助我們判斷程式放大後是否撐得住。Big O 不是精確秒數，也不是單看程式有幾行。

| 複雜度 | 直覺 | 常見例子 |
| --- | --- | --- |
| O(1) | 工作量不隨筆數成長 | 用索引讀陣列元素 |
| O(log n) | 每次排除一大部分 | 已排序資料的二分搜尋 |
| O(n) | 大致掃一遍 | 找未排序清單中的某筆資料 |
| O(n log n) | 比逐對比較省很多 | 常見有效率的比較排序 |
| O(n²) | 每筆再和每筆比較 | 雙層迴圈檢查所有配對 |

**實際場景：** 匯入一萬筆資料，每筆都到另一份一萬筆清單找對應值，可能做近一億次比較。先建雜湊表通常能把總工作量降到接近 O(n + m)，代價是額外記憶體。

**面試回答：**「複雜度是看資料量增加時成本怎麼成長。我會先找反覆掃描或巢狀迴圈，再看能否用索引或雜湊表減少查找；同時評估記憶體成本。」

**追問／易錯點：** 兩個各跑 n 次的前後迴圈是 O(n)，不是 O(n²)。兩層迴圈若內層固定跑 3 次，也仍是 O(n)。實際效能還受資料量、常數、I/O 與配置成本影響；先量測瓶頸。

## 2. 陣列、List 與鏈結串列

**白話與用途：** 陣列像一排編號置物櫃，可直接走到第 k 格。`List<T>` 底層也是陣列，但可擴充容量。鏈結串列像一串尋寶線索，每個節點指向下一個，適合調整已知節點的連結。

| 結構 | 依位置讀取 | 尾端新增 | 中間插入／刪除 | 適合 |
| --- | --- | --- | --- | --- |
| 陣列 | O(1) | 固定長度，擴充需複製 | 維持順序通常需搬移 | 筆數固定、依位置存取 |
| List | O(1) | 攤銷 O(1)，擴容當次 O(n) | O(n) 搬移 | 一般清單，常用預設選擇 |
| 鏈結串列 | O(n) | 已知尾節點時 O(1) | 已知節點位置時 O(1) | 常調整已持有的節點 |

**實際場景：** API 回傳商品清單通常用 List。鏈結串列若要先搜尋插入位置，搜尋仍是 O(n)，而且節點與參考會增加記憶體成本。

**面試回答：**「陣列和 List 適合按位置讀取；List 提供擴容。鏈結串列調整已知節點很快，但隨機存取與找節點較慢，所以一般資料清單我通常先選 List。」

**追問／易錯點：** `Count` 是目前筆數，`Capacity` 是底層可容納筆數。不要只因『常插入』就認定鏈結串列一定比較快。

## 3. Dictionary、HashSet 與雜湊

**白話與用途：** 雜湊像把名字換成櫃子編號，先縮小尋找範圍。`Dictionary<TKey, TValue>` 保存鍵值對；`HashSet<T>` 保存不重複的元素，適合問「有沒有這個值」。

不同鍵可能分到同一區，稱為碰撞；資料結構還要比較鍵是否相等。一般查找平均 O(1)，不是任何情況都保證 O(1)。

**實際場景：** 檢查重複使用者 ID，或先把商品整理成 ID 對照表，避免每張訂單反覆掃商品清單。

```csharp
int[] userIds = { 12, 8, 12, 3 };
var seen = new HashSet<int>();
foreach (int id in userIds)
{
    if (!seen.Add(id))
        Console.WriteLine($"重複 ID：{id}");
}
```

這段平均 O(n) 時間、O(n) 額外空間。

**面試回答：**「Dictionary 是用鍵找值，HashSet 是去重和判斷存在。它們用雜湊縮小查找範圍，平均查找很快，但會用額外記憶體，碰撞多時效能也會下降。」

**追問／易錯點：** 相等的鍵必須有相同雜湊值；雜湊相同不代表相等。自訂物件當鍵時，要一致實作相等判斷與雜湊；放入後不要修改影響鍵相等性的欄位。雜湊值不是可持久保存的唯一 ID。

## 4. Stack、Queue 與樹的走訪

**白話與用途：** Stack 像疊盤子，最後放的先拿（LIFO）；Queue 像排隊，先到的先處理（FIFO）。它們讓處理順序明確。樹像資料夾目錄；圖則能表示更一般的關係，例如朋友網路。

**實際場景：** 復原操作、括號檢查常用 Stack；工作排隊常用 Queue。深度優先搜尋（DFS）先沿一條路走到底，常用遞迴或 Stack；廣度優先搜尋（BFS）一層層找，常用 Queue。

```csharp
static bool IsBalanced(string text)
{
    var stack = new Stack<char>();
    foreach (char c in text)
    {
        if (c == '(') stack.Push(c);
        else if (c == ')')
        {
            if (stack.Count == 0) return false;
            stack.Pop();
        }
    }
    return stack.Count == 0;
}
// 只檢查小括號；時間 O(n)，最差額外空間 O(n)。
```

**面試回答：**「Stack 是後進先出，Queue 是先進先出。DFS 常用 Stack 探索一條路，BFS 用 Queue 逐層探索；無權重圖找最少邊數的路徑可以用 BFS。」

**追問／易錯點：** 圖可能有環，要記錄已走訪節點。DFS／BFS 的圖走訪成本通常是 O(V + E)。遞迴也用呼叫堆疊，深度太大可能堆疊溢位。記憶體內 Queue 不等於可持久保存的訊息佇列。

## 5. 排序與二分搜尋

**白話與用途：** 先把資料排整齊，才能每次判斷答案在左邊還是右邊。二分搜尋每輪把範圍約減半，因此時間是 O(log n)，但前提是資料依相同規則排序，並能有效存取中間位置。

**實際場景：** 在已排序的陣列找門檻值。如果只有一次查找，先花 O(n log n) 排序未必划算；直接 O(n) 掃一次可能更合理。

```csharp
static int BinarySearch(int[] sorted, int target)
{
    int left = 0, right = sorted.Length - 1;
    while (left <= right)
    {
        int mid = left + (right - left) / 2;
        if (sorted[mid] == target) return mid;
        if (sorted[mid] < target) left = mid + 1;
        else right = mid - 1;
    }
    return -1;
}
```

**面試回答：**「二分搜尋是在已排序資料中每次排除一半，查找 O(log n)。我會確認排序前提、邊界和找不到時的結果；如果資料尚未排序，也要把排序成本算進去。」

**追問／易錯點：** 空陣列、單筆、重複值、答案在兩端都要考慮。這段找到任一符合位置，不保證第一個。排序的『穩定』指相同排序鍵保留原本相對順序，不是指速度穩定。
